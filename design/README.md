# Interface concepts

These are visual mockups, not screenshots of a running application. All incidents, metrics, and delivery states are demo data.

## Name shortlist

| Name | Meaning |
| --- | --- |
| Counterforge | Recommended: builds defenses from attacks and retains the Redforge connection |
| AegisLoop | Emphasizes the repeated attack, evaluation, and defense cycle |
| Wardline | A concise name for the boundary that protects agent actions |
| Breachloop | Emphasizes adversarial testing and continuous improvement |
| ForgeWatch | Connects the original project with monitoring and escalation |

CounterForge is the selected project name. The three v1 images below are the original concepts. Files named `counterforge-live-*.jpg` are screenshots of the implemented application.

## Visual direction

Charcoal surfaces, warm ivory type, restrained coral actions, mint defense states, and amber pending states. Clear typography and source/decision evidence are the focus.

- Workspace: useful incident chat beside a live security timeline and action approval.
- Attack lab: matched baseline/defended transcripts, execution evidence, and regression results.
- Incidents: containment, responder escalation, call status, and acknowledgment.

Images are generated with the built-in image-generation tool. The complete generation prompts are saved in prompts.json.
